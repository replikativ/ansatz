# Resumable Expr.findExt runtime profile

The Java engine supports pinned `lean_find_ext_expr` behind original `Lean.Expr.findExtImpl?` at intrinsic 519. Its exact ABI is borrowed predicate object, borrowed Expr object → owned `tobject` result. The original boxed wrapper owns its two parameters and performs their original cleanup. Active explicit logical task mode is required; inactive and recursive paths reject before callback acquisition. Raw borrowed roots, PAPs, imported closures, host-returned raw closures and `makeClosure` remain fenced as for ordinary Find.

Pinned Lean 4.33.1 commit `819816b2e0a3bf405af45ae5c7af2491d8f5bee6` defines FindStep in `Lean/Util/FindExpr.lean` and implements `for_each_fn<false>` / `lean_find_ext_expr` in `kernel/for_each_fn.cpp`. The predicate returns canonical immediate 0 (found), 1 (visit children), or 2 (prune this subtree). Found stops all further callbacks and returns a fresh Some owning one retained found Expr; exhausting or pruning without a match returns immediate None. Invalid callback results stay in the owned receiver escrow on terminal failure.

Traversal is preorder, but skips intermediate App nodes along an application's function spine. The root App and every App reached as an ordinary argument/subtree still receive callbacks. Skipped function-spine Apps bypass the identity cache too; their head is visited before their arguments, in source order. Names, Levels, metadata payloads and literal payloads are not Expr traversal children. Lambda/forall visit domain then body; let visits type, value then body; MData and projection visit their Expr child. A done result prunes only that node's descendants, allowing later siblings.

The existing Find RuntimeAction, callback/AP acquisition packet, Code/Host continuations, found/result escrows and borrowed traversal aliases are reused. Each search records its mode; pending entries have parallel function-spine flags that are copied with the pending aliases through the existing same-memo fork. The two deques carry no additional guest owners. A callback's predicate and Expr copies are acquired once and transferred to ordinary AP; suspension never restarts acquisition. Cache eligibility remains the native dynamic `rc != 1` hint, independent of logical-MT mutation exclusivity. Const, BVar and Sort bypass that cache. Ordinary Find retains its Bool interpretation, partial-App callbacks and existing cache semantics.

Existing structural Expr guards and source-valid, well-founded storage assumptions apply. These guards do not certify nominal AST identity or validate unvisited graphs. Search limits remain 1,000,000 encounters, 100,000 pending entries and 100,000 visited identities, with periodic interruption checks; skipped function-spine encounters also consume the bounded host work allowance. This is not native heartbeat/timing parity, a native ABI bridge, recursive callback execution, a new graph importer or a complete frontend claim. Failed explicit sessions preserve diagnostics and owners under the existing terminal-failure policy; general failed-frame unwinding is not added.
