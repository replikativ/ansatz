# Explicit JVM-layout ShareCommon

This research engine implements original `ShareCommon.shareCommon'` / `lean_sharecommon_quick` at intrinsic 520 over explicitly selected **JvmCarrierLayoutV1**. It performs the pinned postorder rebuilding and canonicalization algorithm. Default unconfigured engines reject execution, including immediate scalar inputs. No identity stub, original guest-body replacement, initializer replay, stateful ShareCommon, native physical equality/hash export, or new public provider default is introduced.

Configure an open idle active-explicit engine once with `JvmCarrierLayoutV1.normalizedValues()` through `configureShareCommon`; the reflective facade supplies `jvm-carrier-layout-v1` and `configure-share-common!`. The immutable policy is inherited by fork, carries no source graph or native authority, and cannot be changed while running or after failure/disposal. Raw ABI recognition is separate from execution activation. An activation receipt must record this actual profile selection and its representation limits; a profile name or caller Boolean does not authenticate source/capsule bytes.

The [original fixture](../test/fixtures/java-sharecommon-runtime/README.md) authenticates the exact two-parameter raw ABI: owned erased placeholder and **borrowed tobject input**, returning owned tobject. The original owned boxed wrapper is unchanged and decrements its input after the call. Raw borrowed external roots, PAP, import, makeClosure and runtime/host-returned closure admission remain fenced; valid direct borrowed FAP and the original owning boxed wrapper/AP are supported. Inactive and recursive execution reject. Source is pinned Lean 4.33.1 commit `819816b2e0a3bf405af45ae5c7af2491d8f5bee6`, `runtime/sharecommon.cpp:295–444`, equality/hash definitions at 13–54, `sharecommon.h`, and `Init/ShareCommon.lean:116`.

The target layout is deliberately precise:

- Long is an immediate logical signed64 value. BigInteger is an exact-class immutable terminal of a separate kind, even when small. Never reinterpret Int(-1) as Nat(4294967295), merge equal Long/BigInteger values, or guess erased native immediate/MPZ allocation classes.
- Valid Unicode Java String terminals canonicalize by exact content and first equal representative. No Unicode normalization occurs; embedded NUL remains content. Lone surrogates and oversized strings reject. Native String capacity, physical RC and allocation provenance are unavailable and are not reconstructed.
- Ordinary constructors are rebuilt fresh ST with exact tag, field count, stored scalar extent/bytes, and canonical child identities. No padding normalization, cached-bit rewriting, semantic Expr equality, or copying of MT/persistence/observed pointer metadata occurs. A 9-byte payload and a stored 16-byte payload remain distinct. Boxed Float/USize/UInt64 retain exact raw bytes, including NaN payloads/high bits/signed zero. Double and private F64Bits remain outside guest OBJ.
- Object arrays visit live slots only and rebuild capacity equal to logical size. ByteArray is a terminal: equality includes live size, capacity and live bytes; unused bytes do not participate. Other scalar-array kinds are unsupported.
- Actual represented Ref, closure, Task and Promise are opaque identity leaves. Validate owner/generation/kind and increment one owned occurrence without descending into cell/captures/task state. Unknown reserved/external/thunk shapes are not newly admitted.

Native ShareCommon compares physical body bytes and metadata, which may distinguish strings with equal content but different capacity or equate some native tagged Int/Nat words. This target contract is maximal sharing under its own declared equality, not arbitrary C++ physical sharing/RC/allocation parity. It preserves values already admitted into the target representation. Source ingress separately owes correct semantic scalar decoding; this operation cannot detect or repair erased native typing/capacity facts. Existing capsules and ledgers are not rewritten or silently relabeled.

The iterative RuntimeAction stores typed traversal frames, borrowed input/memo/canonical aliases, stable per-search child identity IDs, and explicit candidate/result owners. Constructors/arrays allocate before children and process ascending slots. Input identity memoization applies only to nonexclusive input (logical MT is nonexclusive). Completed candidate keys compare shallow canonical children plus exact layout. Hash collisions use full equality. First equal target representative wins. An input constructor is not reused merely because it resembles a canonical output: the native default `m_check_set=false` behavior remains.

Memo/set/identity entries own no guest credits. The borrowed original input remains live through the parked caller; canonical outputs stay backed by owning output frames/fields/result escrows. Child credits transfer once into candidate fields. Duplicate candidate disposal uses existing budgeted native-order release, with an explicit quiet-proof guard rejecting an opaque zero before finalizer dispatch. Exact duplicate child identities are already backed by the prior canonical output, and original opaque leaves remain input-backed, so a valid duplicate disposal cannot consume their last owner. Failure retains partial candidates, result flags, zero queues and diagnostic aliases; no automatic failed-session unwinding is claimed.

The original wrapper still uses ordinary callback-capable input DEC. For a valid immutable input, its opaque leaves also have output owners, so that cleanup cannot consume their final owner. Later explicit output disposal can run real Promise callbacks, suspend at Host/Code requests and fork. Search state is cleared before returning; no interning history or authority-bearing graph survives in a global registry. Fork remaps frames, candidates, raw tables, active keys, IDs and release packets through the engine's existing same memo. Stable local IDs keep in-flight hash buckets valid after object remapping; Java identity-hash collisions are never treated as equality.

Constructor/array cycles reject; opaque Ref/task/closure cycles are not traversed. Source-valid acyclic storage and honest ownership are required. Invalid children can reject when reached after a prefix was allocated. Bounds are 8,000,000 work units; 100,000 frames/memo/canonical/identity entries; 32 MiB aggregate fresh payload estimate; 65,536 UTF-16 String units; 65,536 BigInteger bits; and 1 MiB ByteArray capacity. Incremental work chunks cover at most 256 characters, 1,024 terminal bytes, or 64 object fields; constructor scalar tails are under 1,024 bytes and BigInteger operations are capped at 2,048 limbs. Interruption and overflow reject with state preserved. These are host profile bounds, not native heartbeat or memory measurements.
