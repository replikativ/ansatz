# Source ModuleData exchange: explicit Prelude first

The first slice exports genuinely completed source on its actual engine. It does
not yet reconstruct a checking environment or claim module-loading acceptance.
The separate source-closure unit adds that operation without reloading this
registry. No worker JVM or native execution was performed.

Load source-data-snapshot.clj, source-exchange.clj and their models once after artifact frontend
and runtime-cohort. Reserve lean_ir_export_entries and
lean_get_ir_extra_const_names before early Host registration, then bind their
genuine original compiler guest targets. Authenticate SourceModuleExchange as the
fourth overlay under the actual common CodeReceipt/SourceBinding.

API:

- open-runtime! borrows parent, actual ModuleLease and original fixed Prelude Run.
- export-module! requires an unretired actual EOF CommandReceipt, its wholly linked
  generated Scope and direct parent SourceModules. It invokes the real mainModule
  getter and mkModuleData export helper, then matches every actual CI payload
  against the retained Java checked version. No supplied data/Env/summary can
  replace those roots.
- with-module! lends a snapshot-guarded metadata/CI/Node view, granting no owner.
- retire-file! requires the exact EOF CommandRun, retires it and the actual
  adapter, then normally releases each transferred K/map occurrence. Original
  frontend InputContext/StateRef/setup owners remain in their existing journals.
- owner-packet preserves failed operation custody. There is no automatic unwind.
- take-operation-retirement-owners! transfers only authoritative owned slots from
  a failed operation with no live call/release and a healthy idle engine. Unknown
  ownership intervals reject; a suspended Host request is never unwound/retried.
- take-module-retirement-owners! revokes an exported/retired file's module and
  transfers its actual data/name occurrences. Dependents then fail their guards.
- take-runtime-retirement-owners! terminally transfers the source nursery's known
  occurrences, retaining aliased credits but deduplicating the same shared slot.
  Revoke adapters/Base views first. Borrowed original Prelude and frontend owners
  remain separate. close-runtime! compacts metadata after actual disposal.

The nursery stores only owner-slot maps/status, never full holders or parent
capabilities. This avoids transitive weak-key cycles through module ancestors.
Transferred/retired holders drop driver/engine/native anchors; an exception's
diagnostic capability does not keep the entire closed image alive.

The complete pure ModuleData and module-Name graphs are captured before temporary
cleanup and checked again after cleanup, immediately before sealing and before/
after each borrow. The bounded witness covers imports, CIs, extra names, extension
entry names and payloads, child aliases/order, logical array extents and scalar
bytes. It rejects cycles, references, tasks, closures, external handles and mutable
numeric subclasses. RC and harmless pointer/sharing annotations are excluded;
semantic kind/size, node identity and all payload storage remain fixed. Actual
source-local CI checking shapes are projected read-only and compared after guest
callbacks; imported Prelude proofs are not eagerly projected or replayed.

Keep EOF unretired for export. The current completed-file runner retires EOF;
the first export probe therefore uses the manual M1/M2 loop. Existing finite and
general-file acceptance records are unchanged.

The genuine /2 source helper inspects actual local initializer registrations,
extern attributes, export names and implemented-by mappings. The older /1 field
initializersExecuted=false never proved requirements were empty. Historical
prototype helpers remain unchanged.

For reconstruction, retire the old adapter first and reopen a fresh strict fixed
Prelude Base from the same live ModuleLease/original Run/open store. Never reuse
a revoked Base. The separate source-closure finalizer starts/takes the original
finalizer on a validated closure on the same engine; it will not reset the fixed
Run one-shot marker or seal a preexisting Env. The facades with-closure! and
with-finalized! fail closed until that independent issuer is loaded.

A to B is the first target. Later, compile C over A while retaining B's data as
an unselected artifact, then reconstruct D from exact DFS closure A/B/C. This
avoids cross-engine Node merges and active-association forks. Code readiness,
checked CIs, imports, initialization and callable entries stay separate.

## Source closure implementation

Load source-closure.clj after the export bridge, then its focused models. It uses
the existing opaque Closure/FinalizedSourceRun classes and its own fresh registry;
neither this addition nor its activation reloads the export registry.

- prepare-closure! takes runtime, ordered root SourceModules and a fresh strict
  fixed Prelude Base. It computes exact bounded DFS closure, rejects conflicting
  versions/cycles/CI overlaps, verifies canonical source bodies are ready, then
  runs original source constructors and the genuine graph assembler. Owned
  state/imports/regions are recorded before any later finalizer attempt.
- begin-finalizer! claims a private exclusive runtime marker and internally
  starts the pinned original finalizer on those exact owned inputs. It reuses
  normal root owner/claim machinery without touching the fixed once-only marker.
- poll-finalizer! captures actual IO.ok Env and the original K/map/quot/empty/
  constants helper results. A thrown or returned failure quarantines ownership;
  a ready result revalidates the complete ModuleData/source ledger before sealing.
- with-closure! and with-finalized! are read-only guarded leases. Only the latter
  lends actual successful result anchors to source-base association code.
- take-finalizer-retirement-owners! transfers completed Run occurrences after the
  checked adapter/Base is revoked. take-closure-retirement-owners! transfers
  prepared inputs/regions or the remaining regions after Run retirement. Packets
  remain explicit; pending/failed normal roots are never silently discharged.

Source-only DAG/control/ownership models are included. Genuine A export/import,
then B and a diamond, still require separate runtime probes; source compilation
and metadata models alone do not establish that acceptance.


## B compilation over an actual source closure

After loading runtime-cohort, load the deferred source-module units. Keep the
selected ModuleLease, source modules, Closure and FinalizedSourceRun alive:

1. Open SourceBase from the issued Closure and its actual FinalizedSourceRun.
2. Call source-import-frontend-setup-v1/setup-source! with the parent, that Run
   and the captured B source. The original parser must report the exact closure
   root requests, including ordinary Prelude first.
3. Construct the source authority and checked adapter using that same Base/Run.
4. Call source-import-frontend-setup-v1/open-generated-scope! with parent, adapter,
   Base and Run. Use this scope in the usual M1 receipt/M2 prepare/link loop.

The imported scope lends only canonical ready rows from the selected modules in
that opaque closure. It snapshots each prepared Body identity and rechecks the
Run, Base, source, selected modules, Header and Body on scope operations. It is
bounded to 2048 selected IR rows. Current-file observed but unlinked local IR
still rejects; it cannot fall through to imported or original source code.
Closing the scope revokes host metadata only and releases none of these borrowed
owners. The original scope factory retains its existing Prelude-only behavior.

A checked B expression referring to A establishes a kernel import dependency.
An imported-code execution claim additionally needs an actual decoded FAP/PAP
frontier targeting A: a small definition can be inlined by the original compiler.
Do not infer that claim from source spelling or manufacture a noinline policy.
