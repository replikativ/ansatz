# General command and generated-code receipts: M1/M2

Implementation specification, 2026-10-31. This is a new research route. Existing
identity and arithmetic profiles, their observations and acceptance records stay
separate. No generic runtime acceptance is claimed by this specification.

## Required source authority

The observed frontend companion is a separately authenticated source overlay,
not an original catalogue declaration. It parses exactly once and elaborates
through the original frontend once, preserving the actual parser-return log
before elaboration resets messages. Its pre-elaboration gate has five borrowed
inputs: InputContext, pre-command Frontend.State, Syntax, returned parser state,
and parser MessageLog; its BaseIO Unit reply is direct Long0.

The gate is authorized only at the exact source-produced companion caller/FAP
site, under the actual root invocation. The controller retains the five actual
operands in prepublished owner slots. Original MessageLog.hasErrors is invoked
through HostGuest on the actual parser log; it must return actual boxed false.
The structural/protected-options policy observes this same Syntax and state
before the Unit reply. No supplied approved/verified Boolean authorizes it.
Nested Host/Code demands use the normal bounded driver and preserve gate custody.

The companion returns an owned Observation: eight object fields (input, before
state, Syntax, parser state, parser log, elaboration log, start/end positions),+and four terminal/eoi/exit/import flags. The source provider validates its exact
compiled layout, pointer correspondence with the gate operands, actual appended
Syntax, UTF-8 positions and unchanged captured InputContext/FileMap. Genuine eoi
at captured byte end is completed EOF; exit is a stopped prefix, and import is
unsupported/diagnostic. Terminal alone never proves EOF.

Root integrates the authenticated overlay, canonical Headers, HostGuest outer
gate/helper policy and read-only Syntax/options provider. Generic activation
stays unavailable until these real witnesses exist. The initial structural
policy excludes protected option forms, initialization/export/extern attributes
and unsupported custom command effects. It is not a whitelist of definition
bodies. Effective options changed invisibly by custom macros remain a declared
frontier until guarded at actual consumers.

## M1: genuine base and command history

Add `authority/:artifact-baseline!` as a distinct idle-boundary witness. It checks
the actual source Environment through the pinned compiled layout against the
same live finalized Run: exact map, quotient, imported attribution/header and
disabled diagnostics. It consumes the once-only seed permission, without a fake
ELAB request or helper token. `adapter/establish-base!` retains actual K/map
occurrences into prepublished slots, validates the guarded external Java base,
then publishes version0. Retain uncertainty/failure quarantines the operation
and preserves the slots; it never retries or closes caller resources. The
controller derives the initial Environment from its actual owned state getter
result before any command. No arbitrary caller map is an association constructor.

The adapter retains the existing checked/published version ledger and appends a
bounded event journal at actual check, publication, commit, cleanup and reply
transitions. Count is not reply completion. A successful command requires no
active request, no pending HostCompletion/HostGuest/action, and an ordered chain
of fully replied versions. First generic policy requires monotone ancestry and
final guest map equal to the final replied version, or unchanged version0 when
there are zero publications. It does not silently accept abandoned branches.

`general-command/open-command!` creates an opaque controller before actual start.
`run-command!` captures initial state/IR, invokes only the authenticated observed
companion, validates gate/result/parser/elaboration diagnostics and final checked
association, and retains the complete immutable IR delta. It returns a private
CommandReceipt even when that successful command emits no code. A failed parse,
compiler or owner transition preserves checked history and failure custody but
issues no successful receipt. `retire!` also handles successful zero-code commands.

SourceCaptures remain trusted source-adapter constructors with actual
before-call/result-take observations. Their descriptive maps are summaries, not
authority. The generic provider must authenticate module identity before state
construction, actual source bytes/FileMap, compiler callback and every protected
policy boundary. No host regex separates general commands or invents Names.

Budgets are independent and explicit: initially at most128 commands,512 admitted
publications,2048 cumulative generated rows and bounded borrowed decoding/Name/
UTF-8 sizes. Existing adapter sessions keep their16-publication ceiling; a new
general-session constructor explicitly selects the larger bounded policy. A
generic advancement quantum may be1000..10000, with all real VM/Host/Code/result
and owner-transfer guards retained. Source/engine/thread confinement must hold
through each advance; quantum is not a concurrency or failure-recovery feature.
No optimization claim follows from choosing a larger quantum.

## M2: complete canonical generated fdecls

`generated-batch/open-scope!` is specific to one actual engine/source/adapter and
fresh generic file. It keeps a disjoint local-row/Header registry, with no opaque
token stored back into its own weak-registry value. It cannot mix historical
headerless Program.extend entries into the generic path. Scope close revokes
future resolution/linkage and drops metadata, not guest owners or borrowed leases.

`prepare-batch! scope CommandReceipt` obtains rows only from a live successful
command. Every old typed Name/full row is invariant, and ALL new rows enter the
receipt, including unsupported kinds. Zero delta means no executable batch.
Ordinary fdecls receive canonical frozen generated rows/Headers, with digests
describing captured original compiler output rather than catalogue CAS files.
Private compiler helpers need not have separate kernel CIs or a naming prefix.

Walk complete FnBody/Expr structurally to collect unique direct FAP/PAP targets
and AP occurrences. Resolve each static target as same batch/SCC, earlier linked
local batch, admitted imported source, or authenticated original catalogue.
Register the entire batch and dependency Headers before materializing any body;
materialize with exact unique non-self Headers. This stages SCCs and validates
SSA, joins, ownership and lanes through the existing Java validator. Unsupported
Float32/struct/union lanes stay unsupported. AP records a dynamic frontier and
uses ordinary closure-generation/boxed ABI/owner guards; static completeness is
not a closed dynamic graph or proof that595 host descriptors are implemented.

Reject both exact typed-Name overlap and current runtime display-label collisions.
Never normalize numeric/string components, guess a boxed suffix, replace an
inherited function or add a Host policy during linking. Initializer/export/
redirect requirements need an actual source-policy witness; empty actions cannot
be inferred from fdecl shape alone. Unadmitted kinds/dependencies/preparation
yield an explicit unsupported execution outcome without erasing a successful
checked command. No partial prepared descendant is installed on failure.

After callback-capable temporary cleanup, capture the actual base Program and
stage all descendants privately. `link-batch!` revalidates source, engine, command
version, unchanged base Program and dependency Header identity, then installs
only this actual branch's final prepared descendant once. Generated source code
is never promoted into the pristine original-code seed. Earlier linked local
Headers remain canonical for later commands under the same live scope.

Entry selection uses a genuine checked source declaration and its actual Header/
ABI. Initially codecs may support boxed Nat→Nat and nullary Nat; semantic expected
results belong in acceptance tests, not the receipt issuer. General declaration
checking, successful commands/files, executable entries and reusable source
modules remain distinct capabilities. Import/export/initialization and mutual/
opaque/inductive checking need their own original source/data protocols.

## Acceptance before generic activation

Models cover base0 failure slots, empty/zero/multiple events, monotone ancestry,
parser-log preservation, true eoi versus exit/import, exact gate/source/layout,
complete old/new IR, arbitrary auxiliary Names, SCC and AP recording, canonical
Header/dependency identity, unsupported rows/lanes and atomic failed staging.
Actual probes must include empty/comments, scope-only, theorem-only, parser
recovery before valid code, trailing syntax errors, local protected options,
compiler failure after publication and multiple independent admissions. Then
run the six reviewed source corpus files, recording actual emitted constructors,
CI/IR/dependency/Host boundaries and honest unsupported outcomes. No mutual block,
ordinary implicit Init or reusable module success is inferred from these files.
