# Source-module landing boundary

This unit is based on merged main `89d45546338dd4e3dd58b35051037fb99a8f69e1`.
The historical acceptance, arithmetic and general-command source layers are
unchanged. A third explicit layer accounts for every new or revised Clojure leaf;
the existing canonical core corpus and validation documents remain intact.

The unit adds complete bounded ModuleData snapshots; actual source-module export;
same-engine selected module closures and genuine original finalization; a guarded
composite source Base; exact selected imported-code resolution; and the bounded
project coordinator. It also includes source-authenticated supported-build
queries and release preflight/known prestart-credit custody.

These are reviewed source and retained-runtime observations, not a portable
certificate for arbitrary module data. Each new process must reconstruct the
actual SourceBinding, Headers, ModuleLease, finalized Run, Base, adapter and
command capabilities through their own issuers. Source helper code has no startup
actions; native initializer support remains its separately checked bounded
profile.

The parent recorded actual A-to-B-to-C execution at 512MiB:
`40 ->42 ->43`, with original source headers/EOF/export/finalizers and normal
cleanup of 38 additional occurrences plus 534 runtime roots. The coordinator's
separate first-file test exported and retired one file; this does not claim a
multi-file coordinator or diamond acceptance.

The runtime-cohort build-version provider checks the actual supported build,
source Header/ABI and Unit before returning values. The existing finite driver
and ordinary fixed Prelude Base paths retain their checks. Imported code is
selected by actual module/closure identity and current canonical Header/body
snapshots, never by an arbitrary caller Name map.

Bootstrap pack assembly, its optional importer/child-observer hooks, and the
fixed native tutorial runner are excluded. This split does not enable full Init,
Mathlib, arbitrary plugin initialization, foreign Node transport or a public Java
project-loading API.

`verify-source.py --reviewed-root ACCEPTED_RESEARCH_ROOT` checks all three source
layers, 49 ordered implementation/model units, source/receipt pins and preserved
historical files. `runtime-cohort/verify-source.py` audits the separate provider
package. Both are metadata-only checks; parent retained-JVM model evidence and
the actual chain receipts remain separately identified in
`source-module-v1.json`.

The exact staged implementation additionally passed the parent retained-JVM
model gate: 80 tests / 538 assertions, zero failures or errors. The
[source-module landing validation](source-module-landing-validation.json) pins
the accepted v2 source-model report and build/router report. The initial run's
stale retained SourceExchange definitions were corrected by loading the complete
exact staged function set; no implementation change was needed. That initial
failed report remains history and is not accepted as a passing gate.
