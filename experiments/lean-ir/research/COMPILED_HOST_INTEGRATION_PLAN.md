# Compiled host integration plan

Status: integration plan based on a read-only source audit. References below are repository-relative. M3c execution is implemented separately; kernel/interop composition and fresh hosted cohort acceptance remain distinct gates.

## Main conclusion

The file loader, resident version/ownership model, typed reverse calls and Java facade already exist. Extend their compilation option plumbing and acceptance coverage; do not build another invocation engine, ownership engine, scheduler or loader. The initial audit identified missing typed compiler selection across session reopen operations, composed M4/M5/M6 coverage, and optional-package closure consistency. PR199 repairs the literal package closure and adds its strict CI check; the remaining sections distinguish that baseline from proposed work. Provider/bootstrap distribution and current-cohort genuine hosted acceptance remain distinct integration obligations.

## Gaps identified at the audit baseline

1. **Session propagation implemented separately in PR200.** At the audit baseline, `lazy_runtime.clj:17` already accepts validated compiler options, and `block_compile.clj:249` integrates M3c through the existing driver using `:typed-tail`. However `raw_interop.clj:55` destructures only backend/fuel/cache/threshold and passes only threshold to lazy; `interop.clj:42` passes `{}`. Supplying `:typed-tail` or `:scalar-wrappers` at these APIs silently drops it. Raw `session-options` at `:73`, frontend reopen at `frontend.clj:145`, and `resident_frontend.clj:382` preserve only the old selection. Backend switch explicitly permits only cache/threshold (`raw_interop.clj:209`). A hand-built session can attach a lazy program, but installations/linking/extern extension reopen it without these options, so that is not a reliable public opt-in contract.
2. **Typed facts for newly emitted file functions require a deliberate boundary.** Decide how selected M1 companions/roots/descriptors are prepared from actual installed source declarations after load, and how they are revalidated against each new function map. Preserve opt-in/demand-only behavior; no eager typing of Init and no authority inferred from typed keys. Never carry private normalized provider closures as public validation certificates.
3. **Composed tests remain.** Existing kernel/interop/version fixtures need opt-in new-tier variants, not rewrites. M3's pure scalar subset will normally fall back at object/kernel/host boundaries; meaningful tests must show both an actual typed scalar region executing and the surrounding kernel/callback/ownership behavior. Merely running an all-fallback fixture does not accept compiler integration.
4. **Literal optional package closure repaired separately in PR199.** At the audit baseline, `block_compile.clj:9` unconditionally requires `prototype.scalar-wrapper`, absent from `modules/lean/runtime-closure.edn`. `build.clj:16` audits literal prototype dependencies and will reject that omission. The separate bounded pinned-core packaging gate covers the reviewed literal additions; it does not accept the current core or typed compiler distribution. Typed-tail dynamic requires in `block_compile.clj:255` are outside that literal audit: explicitly account for typed-tail execution/emitter/preparation/M1/M2 sources and pinned Pattern availability in an optional packaging policy. Keep Pattern absent from normal core paths; do not weaken source inventory checks to make packaging pass.

## Small reviewable PR sequence after M3c acceptance

1. **Session compilation options (PR200):** one validated immutable public compiler-selection/options contract, threaded through raw/interop constructors, session-options, linking/installation, frontend reopening, with-externs and backend roundtrips. Rebuild/revalidate plans for changed code; preserve original sessions/caches. Test malformed configs before state adoption, opt-in/default separation, supported backend switches, cache separation and protected authority unchanged. Default behavior stays identical.
2. **M4 boundary composition:** add small actual guest kernel admission/projection fixtures surrounded by selected scalar execution; cover checked/unchecked/wrong-version roots, protected helper/encoder replacement, projection borrow/metadata and retained siblings. Run reference/mutable/JVM with compiled-route evidence and exact fuel snapshots where suspension is possible. No new authority API.
3. **M5 boundary composition:** test Clojure→Lean scalar/Nat/String and Lean→host typed externs with new-tier selection; include scalar work before/after callbacks, host binding changes, same-world reentry, aliased owners, typed EIO success/error, host failure/checkpoint pairing and no retry. Expose any necessary facade option as a thin adapter. Extend existing Java consumer to selected execution; do not add a Java scheduler. IO exposure through the facade is a separate small adapter PR only if required by the agreed user-facing profile.
4. **M6 edit acceptance:** one REPL performs A→edited B with distinct retained handles/Worlds, old/new/old calls, unchanged plan reuse, changed inlined wrapper/source dependency invalidation, stale/wrong-image handle rejection and sibling preservation. Use existing version/context model; include a changed dependency requiring re-elaboration rather than treating cached caller reuse as a substitute.
5. **Optional module package repair/integration:** reviewed static closure repair, explicit typed compiler dependency/profile, current jar-only Clojure+Java tests with no checkout runtime paths, documented capability/provider profile. This can land earlier as an independent packaging fix; genuine current-cohort hosted acceptance follows only after runtime settles, using separately authenticated current source/class cohort. Do not refresh historical receipts/hashes.

## Focused contract questions / research

- What precise supported selection API binds demand-only typed facts to newly compiled file code, while installs and backend changes reopen sessions? Resolve using existing `prepare-program-options` and resident checkpoints, not a second compiler/session registry.
- Retained A handles are invoked with their retained A Context; B uses its B Context. FileHandle validation remains unit identity within the supplied Context. No automatic latest-name lookup or A-handle reinterpretation in B is introduced.
- The initial release profile is provider-first with documented bootstrap prerequisites, matching the existing optional jar. Turnkey bootstrap distribution/authentication/resource ownership is separate work.
- Does the user require public IO/EIO/graph APIs in both facades, or is synchronous Nat/String sufficient initially? Lower layers support more than facade, but coverage must not be advertised as accepted source-language coverage without tests.
- No upstream fact needed network research for this audit. Signed integers/general aggregates/native Lean FFI and whole Init/mathlib performance are separate work, not prerequisites for the minimum JVM hosting slice.

## Bounded composed boundary slice

The first composed fixtures are deliberately narrower than completion of M4/M5:
actual checker admission and independent emitted scalar execution share a World;
raw callback reentry restores an outer continuation; typed String callbacks
delegate the existing ownership adapter. All tiers compare complete states and
JVM evidence pairs the actual typed artifact with its executed specialized hook.
The host kernel anchor and hand-built callback callers are explicit fixtures, not
a hosted Lean Environment or new source admission. No Java, frontend or EIO
acceptance is inferred. See the implementation spec's bounded composition section.

The [bounded validation record](../measurements/compiled-boundaries.json) records
three passing tests (1,209 assertions) on the inherited frame+Nat resident runtime.
This is partial composed boundary evidence, not completion of M4/M5 or a freshly
