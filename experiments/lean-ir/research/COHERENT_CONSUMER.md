# Manifest-pinned coherent consumer infrastructure

This is experimental host infrastructure for one current source/class cohort
consuming the unchanged producer50f checkpoint. It is not a public turnkey
Lean-on-JVM release or evidence that the complete frontend agenda has succeeded.
The archived checkpoint, original producer sources and native Source artifacts
are external prerequisites, not bundled test fixtures.

The separate compatibility profile is
`ansatz-producer50f-coherent-frontend-consumer/1`. Historical profiles keep their
fixed inventories and options. Their earlier frontend results do not establish
acceptance for this new cohort. The producer implementation/recipe identity,
loaded consumer implementation identity, and composition-contract identity are
separate checks.

## What the contract binds

The externally reviewed contract closes the complete source/resource/Java-class
inventory, controller entrypoints, nine helper source/IR pairs, original casesOn
extern row, construction redirect, finite limits and ordered stages. The required
pure helper value runs after sealing and before Project work; it is not replaced
with a host-seeded value or native initializer replay.

`globals-consumer-factory/coherent-contract` returns the composition retained by
that actual identity-issued factory. Preparation obtains it through this accessor,
not a caller-supplied reconstruction of its descriptor. Source/IR preparation
happens before profile sealing. The same consumer extern-lowering callback must
reach later prefix and program-install paths so subsequent original casesOn rows
retain the checked redirect. Construction remains distinct from kernel admission.

The current implementation includes a private owner ledger for controller
failure paths. It records committed dispositions before a later cleanup attempt;
unknown partial states preserve canonical escrow and the Source lease. A summary
or diagnostic never grants permission to retry a failed control or infer disposal.

## Prepare and review a pack

The tools live in [`scripts/coherent`](../scripts/coherent/PACK_PREPARATION.md):

1. Commit the final reviewed source cohort and capture its Git blobs.
2. Compile all 23 current core Java sources plus `TypedLongMemo` into one empty
   class directory; record the actual 48 outputs and passed compiler receipt.
3. Supply explicit pins for original producer build/artifact inputs, checkpoint
   siblings, native Source sidecars, helper artifacts and source fixtures.
4. Generate a candidate contract and launch manifest with `REVIEW_REQUIRED` status.
5. Independently review their exact bytes, classpath, physical roots and expected
   hashes before a finite guarded bootstrap invocation.

The final dependency basis uses data.json 2.5.1. The classpath is exactly the four
reviewed dependency jars, selected source root and fresh class root. Bootstrap
rejects extra source/class/AOT providers, manifest-linked jars, multi-release
project providers, stale identities, existing output paths and symlink ancestors
before any project namespace loads. Only one exact authenticated declaration index
may resolve outside the pack. Declaration blobs remain independently hash/Name
checked on demand; this is not a general filesystem sandbox.

The old 43-row import helper has explicit derived-subprogram provenance: its
manifest and all 42 declaration raw lines are byte-identical selections from the
source-backed 56-row export. The selection reconstructs the original old artifact
hash. This does not claim a recovered old standalone source or a complete 43-row
compilation of the newer source.

Two independent fuel limits must not be conflated: RAW invocation fuel is
500,000,000, while Java imported checking retains the established 20,000,000
per-declaration limit. Neither number is a wall-clock deadline. Resource guards
have separate heap, process-group RSS, host-available-memory and wall limits.

## Fixture-free CI

`bin/run-unittests` runs [`scripts/test-coherent.py`](../scripts/test-coherent.py).
It resolves the repository root's direct dependencies with CLI `-Srepro -Spath`,
so an installation default cannot replace the transitive Clojure pin through the
experiment project. It compiles one fresh 24-source Java cohort, checks the actual Java class origins,
loads the six controller namespaces without calling them, and executes the exact
28 contract/stage/owner test Vars. A parameterized regression covers nine legacy
constructor APIs across eight historical profiles using the real issuance registry,
descriptor and invoke routes; only the already-authenticated construction envelope
is modeled. Ten Python tests cover metadata, typed Names, path handling and the two
distinct fuel ledgers. A separate JVM gets copied source/resources physically
excluding coherent namespaces and AOT output, then exercises legacy loading and
its unchanged option rejection. These tests require no Lean SDK or checkpoint.

They do not establish a closed production runtime, archived-factory reconstruction,
full restore, kernel admission, guest execution or frontend acceptance.
