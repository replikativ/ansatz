# Bounded Project discovery

`prototype.project-discovery/discover-project` captures an ordinary classic source dependency graph and returns a descriptive graph plus the actual updated prepared packet. It composes the [source provider](SOURCE_CAPTURE.md) and [bounded header operation](SOURCE_HEADER_DISCOVERY.md). It does not compile, import, publish, adopt a Context, or issue checked graph capabilities.

The caller provides a coherent prepared packet, its independently captured resident configuration, a canonical source provider, ordered root module Names, and a bounded list of native module Names. Names use Lean's structured wire form with nonempty string segments, for example `["str" ["anonymous"] "A"]`. Numeric, dotted, path-like, malformed Unicode and oversized segments are outside this filesystem subset. The native list only stops discovery walks; it does not establish a checked native base.

The request is exactly `{:roots [...] :native-modules [...] :provider provider}`. Options are exactly `{:configuration configuration :header-limits header-limits :limits project-limits :budgets budgets}`. Header limits are the nine explicit bounds required by the header API. Project limits are explicit positive Long values:

- `:max-roots`, `:max-native-modules`, `:max-modules`, `:max-depth`, `:max-edges`;
- `:max-source-bytes`, `:max-header-output-bytes`;
- `:max-name-nodes`, `:max-name-bytes`, `:max-total-name-bytes`.

Budgets are `{:helper-fuel per-call-cap :attempt-fuel aggregate-cap}`. Each header call reserves at most the smaller of its per-call cap and remaining attempt fuel. Successful work uses the header operation's observed charge. Failed unknown work keeps its reservation without inventing observed steps. Header output has no actual byte-count field, so discovery conservatively reserves the full header `:max-output-bytes` for every attempted call. This scalar is a reservation bound, not measured output size.

The returned value has `:packet`, `:graph`, and `:progress`. Its `:helper-calls` counter counts attempted public header operations, including a possible rejection before raw guest execution; it is not a raw invocation count. The graph contains ordered roots, descriptive native names, captured source nodes, and dependency-first source `:order`. Every node retains its exact immutable text, byte count, digest, parsed header, and ordered dependencies. Duplicate root and header occurrences are preserved in their original inputs; capture and scheduling deduplicate module identities in encounter order. Raw import occurrences—including implicit Init/meta Init and duplicates—count against `:max-edges`, and their Name bytes count before deduplication. Depth counts source nodes along a path, with native leaves excluded. Shared subtrees still contribute their full longest path.

Discovery reads each source module once per attempt, parses that exact captured text, and threads every updated World/session through the same scratch branch. The caller should fork once before discovery and adopt its final packet once after success. Later compilation must use the retained captures rather than rereading their paths. All-native requests still run host-only packet/configuration readiness; they do not run a header helper or gain native authority.

Each capture preserves the provider's canonical root identities and only lowers its per-file byte limit to the remaining aggregate allowance and the header source bound. Filesystem assumptions remain cooperative: captures are immutable after reading, but concurrent edits can produce different versions across files or mixed bytes within a file. There is no project-wide filesystem transaction or I/O deadline. Zero remaining source allowance rejects before the next capture, including an empty file.

Cycles, missing files, parser diagnostics, unsupported module Names and exhausted bounds terminate the attempt. Exception evidence retains the entry, actual latest packet, partial graph and budget state. A successfully returned header packet is saved before Project-only checks; a malformed header retains its nested owned raw result. No automatic retry, resource close or cleanup occurs in the operation. Test fixtures close their own resources during teardown, so retained test diagnostics do not promise live resumability.

Discovery does not establish that the graph is compilable by the current checked graph profile. In particular, explicit native dependencies other than the supported implicit Init/meta pair require a separate compilation-selection design; the current graph root API accepts issued source nodes. Native-only reset, general loading, checking and Project compilation remain separate integration gates.

The [complete optional validation](../measurements/project-discovery.json) passed 997 tests / 93,591 assertions, including all six Project discovery tests. An earlier six-test run had one failed assertion because its modeled parser diagnostics had the wrong shape; the corrected single test passed 19 assertions before the complete run. These records remain separate. Tests use real provider/filesystem captures and production packet, ownership and budget code around an explicitly modeled fixed header target. They do not execute the complete actual parser IR or establish genuine frontend compilation.
