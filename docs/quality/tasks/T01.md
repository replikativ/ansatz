# T01: simp fails loudly (Plan Phase 1.1/1.2, simp)

REPL port: 7911

## Goal
Make `simp`, `simp_all` and `simp … at h` fail loudly instead of silently returning "no progress"
or an unproved rewrite. Today a programming error inside simp turns into a skipped hypothesis, a
rewrite without a proof, or "made no progress". One such case (an NPE in conditional hypothesis
rewriting, swallowed by `(catch Exception _ ps)`) cost the spindel probe several hours.

## Scope fence
You may change `src/ansatz/tactic/simp.clj`, `src/ansatz/tactic/discr_tree.clj` and
`src/ansatz/simp_index.clj`, and add tests under `test/ansatz/tactic/`. Do not change `core.clj`,
`basic.clj`, `grind*`, `instance.clj` or `omega*` (other tasks own them). If a fix needs them, say
so in your result instead.

## Work
1. Classify every broad catch in `simp.clj` (about 53), `discr_tree.clj` and `simp_index.clj`.
   Search for `catch Exception`, `catch Throwable`, `catch RuntimeException` and the specific
   JVM exceptions.
   - Legitimate "this lemma/step does not apply": narrow to tactic errors (`ExceptionInfo` with
     `:kind :tactic-error`). If the code below throws something else for "does not apply", make
     it throw a tactic error.
   - A programming error being hidden: remove the catch and fix the bug it hid.

   List every site and your decision in the result file.
2. Pay particular attention to these sites:
   - The congruence/funext proof builders that fall back to returning a rewritten expression
     **without a proof** (around simp.clj:198/232/267/296/2505, as of the coordinator's audit;
     line numbers drift). A rewrite whose proof cannot be built must be abandoned (no result),
     never returned as if definitional. Lean never does that.
   - In `simp-all-pass`, the per-hypothesis `(catch Exception _ acc)` and the goal-simp catches.
   - `ensure-ble-eq`.
   - Instance synthesis inside discharge (`synthesize*` under `catch Throwable`).
3. `:max-depth 20` in `simp-expr*` stops silently and returns the expression unchanged. Lean has
   no such depth cap (`Simp.Config` has `maxSteps`, and ansatz's `*max-simp-steps*` already raises
   an error). Remove the cap, or if it guards real non-termination, make it raise a tactic error
   naming the limit. Check whether the depth counts subterm nesting or rewrite chains; a deep but
   finite term must not be cut off.
4. Do NOT change the user-facing semantics otherwise. That excludes "simp made no progress" as an
   error, and changes to the default lemma set; both are later tasks.
